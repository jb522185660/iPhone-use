# 已安装后的增量更新

用于用户要求更新 iPhone Use、检查更新，或安装时发现已有完整安装。普通手机任务不自动查更新。默认只更新当前 Agent；用户明确要求时才同步其他 Agent。

## 判断需要更新哪一层

1. 从当前宿主的插件清单、MCP 配置和技能加载位置识别实际安装。区分插件内技能、独立技能副本、符号链接和账号内上传技能；不能只更新源码目录就声称宿主已更新。仅维护技能时读取本地安装信息即可，不为证明已安装而启动手机或调用 READY。
2. 优先使用用户配置的来源；本 fork 的默认来源是 [jb522185660/iPhone-use](https://github.com/jb522185660/iPhone-use)。取得目标提交或源码包，保留现有 checkout 的未提交改动；需要获取远端时 fetch 后在独立临时目录查看目标内容，不用 reset / clean 覆盖用户工作区。离线时说明只能与本地已有来源比较，不声称已核对远端最新。
3. 比较实际文件内容和来源提交，而非只看 `plugin.json` 的版本号。同一插件版本也可能有技能更新。已知上次来源提交时查看其至目标提交的 diff；缺少基线时比较实际加载的技能及安装包内容，来源或本地定制无法辨明时保留它们并报告具体不确定项。
4. 确认新技能要求的工具名称、参数和行为能由已安装运行时提供。宿主适配产生的正常文字差异要先转换到同一种宿主格式再比较，不能当成用户改动或需要替换运行时代码的证据。

| 比较结果 | 更新范围 |
| --- | --- |
| 无差异 | 不写文件，说明已是最新，并注明比较到的来源提交 |
| 仅技能及配套资源变化，兼容已安装工具（其他差异仅为 README / 更新说明） | 仅同步当前 Agent 有变化的技能文件，不执行整包安装 |
| 服务、工具协议、UI、依赖或宿主运行适配也变化 | 单独说明实际需要的插件 / 运行时更新；按当前宿主方式更新这些层，保留已有设备配置和有效 PUA 构建。存在运行时变更时不能将整次更新称为“仅技能更新”，也不等于需要从头配置手机 |
| 新技能依赖尚未安装的工具或协议 | 不单独替换为不兼容的新技能；先处理必要的运行时更新，或保留旧技能并说明阻塞 |

## 只同步当前 Agent 的技能

- 同步范围是 `skills/iphone-use/`、`skills/iphone-use-setup/` 中实际变化的内容，包含 `SKILL.md`、引用文档及所需资源；不能只替换入口而漏掉引用文件。无变化的技能不重写。
- 先暂存并检查目标内容，再备份要替换的旧文件；按确认的上游基线合并本地定制，只清理已知由本项目管理且目标中确实删除的文件，不删除未知文件。缺少可用合并基线且存在本地定制时，保留冲突文件并说明，不能强覆盖后宣称完成。
- 按宿主实际技能安装方式同步或重新导入，保持技能名与启用方式。独立文件型技能可直接更新实际加载目录；插件管理型技能先使用宿主支持的更新方式，未提供局部更新时只在其允许的范围内更新技能，不能假定改缓存就是持久更新。若必须整包刷新，则明确说明限制；仍保留 PUA、签名、设备和 MCP 配置。
- 对按账号上传的技能，准备更新后的技能目录并通过该宿主的技能管理入口替换；本地文件准备好不等于账号内技能已生效。需要用户完成上传时给出准确位置和目录，记录为待导入，而非已完成。
- 符号链接应核对其实际目标是否属于本次来源和授权范围；不要盲目写入链接指向的其他项目，也不把链接替换成普通目录。

已有宿主适配必须继续使用，不能用通用文本覆盖其工具名或入口规则：

| 当前安装形式 | 技能处理方式 |
| --- | --- |
| 通用文件型技能（例如已单独导入的 Claude 技能） | 使用源技能完整目录，更新该宿主实际加载的副本 |
| WorkBuddy | 暂存 Markdown 时使用 `workbuddy/host_text.py` 的 `skill_text(relative, text)`；非 Markdown 资源按原内容同步。不要仅为技能更新运行 `workbuddy/install.py`，它会连服务和 MCP 配置一起处理 |
| 豆包工作 | 暂存 Markdown 时使用 `doubao/doubao_text.py` 的 `skill_text(relative, text)`，保留配套资源，再替换宿主中已启用的两个技能；仅运行本地安装器不能更新账号内已上传副本 |
| 插件内技能（例如 Codex 插件） | 先确认宿主实际使用的插件来源和加载路径。使用可用的技能 / 插件更新能力，并核对实际加载内容；没有可靠局部更新方式时说明限制，不自动改注册信息或声称已完成 |

当前包没有宿主适配源码时，从同一目标提交的仓库取得适配函数，不混用不同修订。不要调用全量安装器来代替这些文字适配函数。

## 验证与更新说明

核对实际加载位置的文件与暂存后的宿主版本一致、引用文件齐全、原有本地定制仍保留；如果只能准备导入文件，明确区分已准备与已加载。使用宿主已有的热重载、重新导入或重连方式使其生效；按实际能力说明是否需要新会话，不一律要求重启 Agent，更不重启手机服务。无需为技能更新操作计算器、打开手机屏幕或额外测试手机。

根据这次实际应用的 diff 和对应提交说明提炼用户可感知的变化，不照搬整个 CHANGELOG，也不把旧功能当作本次新增。回复包含：

- 结果：已更新、已是最新，或已准备但待导入 / 仍有冲突。
- 范围：当前 Agent、发生变化的技能及来源提交；插件版本未变时可用提交号或内容摘要标识修订。
- 内容：本次确实应用的几项行为变化；仅技能更新时注明手机服务和配置保持原状。
- 生效：已加载的证据，或准确的宿主重载 / 导入步骤。未安装的运行时更新另列，不能混称为整个插件已更新。
