# 浏览器手机面板与命令

网页和原生面板共用画面、点击、拖动、滚轮、工具栏、操作锁及认证暂停规则。默认只监听 `127.0.0.1`，供连接 iPhone 的同一台 Mac 使用；默认端口 18101，被其他程序占用时使用空闲端口。以返回的 `browser_url` 为准，链接带有本机访问令牌，不固定拼接。

## 启动与展示

`pua_setup(action="start")` 确认服务启动成功、`pua_ready` 成功或 `pua_screen()` 打开屏幕后，结果包含 `browser_url`。本会话首次处理屏幕入口时给出 Markdown 链接，链接名称使用「手机屏幕」，目标直接使用实际返回的 browser_url；后续工具再次返回链接不要求重复提示。

本会话首次取得有效 READY 后，尽力打开一次屏幕入口；两个技能共用这一次处理。优先复用正常的原生面板；原生不支持、未验证、黑屏或持续连接中，而侧栏浏览器可用时，主动用宿主浏览器工具打开实际 `browser_url`。已有手机页面就复用，旧链接失效时更新原页，已关闭才新开。用户明确不展示时遵从。

页面打开成功与侧栏展开是不同状态。宿主提供显示或聚焦能力时可以使用；缺少该能力、无法确认或失败时，不强求、不循环检查、不重复创建页面。首次回复可写「手机屏幕已在侧栏浏览器打开：」，后接名称为「手机屏幕」、目标为实际 `browser_url` 的 Markdown 链接；已知仍收起时提示点击浏览器侧栏。未打开成功则说明实际状态并给链接，不宣称已打开。没有侧栏浏览器时提供链接，用户要求后再打开系统浏览器。

后续任务默认沿用，不主动检查可见性、重新开页或重复提示，除非用户要求展示或修复预览。展示失败不阻塞健康的控制通道，不为展示重复 READY 或重启 PUA，也不绕过锁屏 / 认证暂停。

宿主限制示例：2026-10-20 的 Claude Desktop 实测已自动创建手机网页，但侧栏需要用户点开。[Claude 官方说明](https://code.claude.com/docs/en/desktop#preview-your-app)也说明面板未打开时可点击聊天卡片的 Open；[相关反馈 #88965](https://github.com/anthropics/claude-code/issues/88965)记录了页面工具成功但侧栏仍隐藏的现象。这不应触发反复开页或重启手机服务。

从项目或已安装插件根目录运行（不要照抄其他用户的缓存路径）：

```sh
python3 scripts/browser.py start
python3 scripts/browser.py start --open
python3 scripts/browser.py status
python3 scripts/browser.py stop
```

`start` 只启动或复用网页服务，不启动或重装 PUA。`--open` 是用户要求时打开系统浏览器的选项。`status` 可重新获取访问链接，`stop` 只停止本项目拥有的网页服务，保留 PUA。状态输出是 JSON。

要同时启动已配置设备和网页，可运行 `python3 scripts/launch_screen.py`；它会选择 USB 设备、复用构建、验证 READY、启动网页并打开系统浏览器。加 `--no-open` 只打印链接。`--install-desktop` 仅创建或更新桌面快捷方式，不操作手机。

## 恢复与限制

页面关闭或隐藏后停止无效采集，重新打开可恢复；多个网页复用服务。锁屏、认证暂停、忙碌或过期画面不能操作。认证仍由用户在手机上完成，按主技能的实际确认流程恢复。

`browser_error` 单独说明网页服务错误，不否定成功的 READY。检查 `browser.log`、Node.js 发现和网页服务状态；重启网页不重启 PUA。不要重复未确认结果的手势。网页刷新仍失败时检查真实状态，不反复重签名或重建。访问令牌和运行记录保存在私有运行目录，重启网页服务后使用新返回的链接。
